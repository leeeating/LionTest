# 觀念筆記：討論中挑選可遷移的觀念

## 流程

1. **使用者在討論中問**哪些觀念值得記。
2. **AI 提出 3～5 個選項**，從目前的討論與本專案素材挑（`ai-collab/process-log.md`、`part_b/`、`notes/`、`part_b/evidence.md`、對話脈絡）。每個選項一行：
   `觀念名稱｜為什麼可以帶到其他專案｜在本專案哪裡出現`
3. **使用者選**（可多選，也可自己提）。
4. **AI 寫筆記**，一個觀念一份。寫之前先看 `LionDEExam/submission/learning/README.md` 的索引，已有的觀念改成補充原檔，不重開新檔；寫完把該觀念加進索引表。

## 選題偏好

- **優先**：可遷移的 SWE 技能。例如套件／工具的用法（uv、duckdb、pyspark、delta、ruff、git）、SQL 寫法與模式（window function、去重、join 膨脹檢查）。
- **不算**：只跟本題資料有關的事實（某張表有幾筆重複、某欄位的值域）。這類放 `notes/` 或 `evidence.md`。

## 筆記位置與格式

位置：`LionDEExam/submission/learning/<kebab-case 觀念名>.md`，約一頁。建議結構：

```markdown
# <觀念名稱>
<一句話說明>

## 白話版
<必要時用 Python 或 C# 類比>

## 什麼時候用、什麼時候不要用

## 最小可跑範例
<程式碼；能在本機 `uv run` 執行的，附實際輸出。不能跑就標「未執行」>

## 常見的坑
<優先用本專案踩過的例子>

## 本專案出處
<函式名＋可搜尋片段，或 process-log 事件標題；不寫行號>

## 官方文件
<實際讀過的連結；沒讀到就標「未證實」>
```

## 寫法

- 繁體中文，技術名詞保留英文；結論先行、簡短。
- 範例輸出必須是這次實際執行的結果，不憑記憶寫。

## 紀錄

寫筆記不用記 process-log 事件。寫完在回覆最後一行寫「已記錄觀念筆記：<檔名>」。
