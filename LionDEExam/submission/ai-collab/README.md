# AI 協作紀錄

這份 take-home 全程與 AI（Claude Code）協作完成。本目錄說明每項產出是怎麼做出來的。紀錄分三層，加上最底層的原始對話，粒度由粗到細：

| 層 | 位置 | 粒度 |
|---|---|---|
| 報告 | 各 Part 繳交物、`ai-collab-report.md`（一頁 AI 協作報告） | 結果文件，給閱卷者讀 |
| 過程 | `process-log.md` | 使用者的思考過程，依部分分節的事件 |
| 改動 | git log | 每次檔案改了什麼；commit 訊息末行 `Session: <session id 前 8 碼>`（從 2026-10-10 三層制度起的 commit 適用） |
| 原始 | 另附的 session jsonl 壓縮檔 | 完整對話（含 subagent 與過長的工具輸出），原始 Claude Code session log 去識別化後壓縮，繳交時另附 |

追溯一個結論的路徑：報告 → process-log 事件 → commit → 對話。

另有三個「規則來源」，不算紀錄層：`prompts/` 收 AI 寫的規則 prompt，`memory/` 收 AI memory 的原始檔照錄，專案 skill 的副本在 [`prompts/skills/`](prompts/skills/README.md)（實際生效的是 repo 根目錄的 `.claude/skills/`）。

## process-log.md 事件格式
全專案一份。**記使用者的思考過程，不求嚴謹**：他當時質疑什麼、為什麼這樣決定、方向怎麼轉變，能引用使用者原話就引用。AI 做了哪些改動交給 git；AI 的錯誤仍要記，一句話帶過，但要寫出原本產出什麼、錯在哪。

**依部分分節**：依工作內容分成幾個部分（`## 第一部分：…`），每部分開頭一段說明範圍，事件用 `###`，部分內大致依時間排列；不同部分在時間上可以交錯。

```
### YYYY-MM-DD｜<Part 或「全專案」>｜<一句話標題>

<一到兩段：使用者怎麼想、怎麼決定；以讀得順為準，不限句數>

- 依據：<commit hash>
```

依據寫 commit hash 就夠了，還沒 commit 的寫 `〔待 commit〕`。有 ADR 時只寫「見 ADR-NN」。AI 起草、待使用者改寫的內容標 `〔待使用者確認〕`。

**什麼算事件**：方向轉折、使用者定案、AI 出錯被抓到。使用者的質疑只有在**改變了報告或決策**、或**抓到 AI 的錯**時才單獨記成事件；只是為了理解的提問，在相關事件裡一句帶過，答案放 `notes/` 或 `learning/`。

## 一頁報告的素材來源
| 報告要回答 | 從 process-log 找 |
|---|---|
| 如何把任務拆解給 AI（附關鍵 prompt） | 使用者決定分工、委派的事件 |
| AI 在哪裡出錯或不足，如何發現並糾正 | 記到 AI 錯誤的事件（驗收 agent、使用者、執行結果、AI 自查發現） |
| 哪些部分刻意不用 AI 或不採納建議，為什麼 | 使用者定案、否決 AI 建議的事件 |

## 完整對話紀錄的處理規則
- **保留**：使用者每則訊息、AI 每則回覆、每次工具呼叫與結果、subagent 完整對話、系統注入的設定內容（折疊顯示）。
- **遮蔽**：email、姓名、系統帳號名、現職公司名、與本考題無關的其他專案名稱，以 `〔已遮蔽：…〕` 標示；本機家目錄路徑改寫為 `~`。遮蔽字串清單存於不進版控的本機設定檔。題目內容不遮蔽。
- **截斷**：超過 60 行的工具輸入或輸出保留前 40 行，標示 `〔輸出截斷，共 N 行〕`。對話文字不截斷。
- **未收錄**：AI 內部推理（thinking）。
