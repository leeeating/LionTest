# AI 協作紀錄

這份 take-home 全程與 AI（Claude Code）協作完成。本目錄說明每項產出是怎麼做出來的，分兩層：

| 層 | 檔案 | 內容 |
|---|---|---|
| 主文 | `process-log-<part>.md`（每個 Part 一份） | 每個任務照六步驟流程抽象整理：誰先看、怎麼拆、交給 AI 什麼、怎麼驗證、AI 錯在哪、最後怎麼決定 |
| 附錄 | `transcripts/*.md` | 完整對話紀錄（含 subagent），由 `export_transcripts.py` 從原始 session log 轉出，只做個資遮蔽與長輸出截斷 |
| 報告 | `ai-collab-report.md` | 一頁 AI 協作報告，從 process-log 彙整 |

## 六步驟流程
| 步驟 | 主導 | 記錄什麼 |
|---|---|---|
| 0. 你先看 | 使用者 | 交給 AI 前自己看了什麼、初步判斷 |
| 1. 拆解 | 使用者＋AI | 子任務切法，哪些交給 AI、哪些自己做 |
| 2. 委派 | AI | 關鍵 prompt 原文（過長可摘錄，標「摘錄」） |
| 3. 驗證 | AI | 檢查方法與結果 |
| 4. 修正 | AI | AI 錯在哪、發現者、怎麼改、證據 |
| 5. 定案 | 使用者 | 採用什麼、為什麼，使用者親筆 |

## process-log-<part>.md 條目格式
每個 Part 一份檔，開始做該 Part 時建立；檔內**每個交付物一節**。任務編號 `<P>-NN`（`<P>` 為 A／B／C／M）連續、不重用；修正項編號 `<P>-NN.k`。步驟 5 的決策若有 ADR，只寫一行「見 ADR-NN」。

```
## <P>-NN｜<任務標題>
- Part：<A / B / C / D / E / F / 環境>
- Session：<session id 前 8 碼>，<日期>
- 產出檔：<路徑>

### 0. 你先看
### 1. 拆解
### 2. 委派
> <prompt 原文>
### 3. 驗證
- <方法> → <結果與證據>
### 4. 修正
- <P>-NN.1｜<AI 原本產出什麼> → <錯在哪>。發現者：<使用者／執行結果／驗收 agent／AI 自查>。修正：<改成什麼>。證據：<…>
### 5. 定案
<使用者撰寫；AI 草稿標〔待使用者確認〕>
```

沒有內容的步驟寫「無」並說明原因，不刪除。尚未完成的步驟寫 `〔進行中〕`；AI 起草、待使用者改寫的內容標 `〔待使用者確認〕`。

## 一頁報告的素材來源
| 報告要回答 | 取自 process-log 的步驟 |
|---|---|
| 如何把任務拆解給 AI（附關鍵 prompt） | 1、2 |
| AI 在哪裡出錯或不足，如何發現並糾正 | 3、4 |
| 哪些部分刻意不用 AI 或不採納建議，為什麼 | 0、5 |

## 完整對話紀錄的處理規則
- **保留**：使用者每則訊息、AI 每則回覆、每次工具呼叫與結果、subagent 完整對話、系統注入的設定內容（折疊顯示）。
- **遮蔽**：email、姓名、系統帳號名、現職公司名、與本考題無關的其他專案名稱，以 `〔已遮蔽：…〕` 標示；本機家目錄路徑改寫為 `~`。遮蔽字串清單存於不進版控的本機設定檔。題目內容不遮蔽。
- **截斷**：超過 60 行的工具輸入或輸出保留前 40 行，標示 `〔輸出截斷，共 N 行〕`。對話文字不截斷。
- **未收錄**：AI 內部推理（thinking）。
